# Math Microbenchmark Checkpoints

The rule set in `base.egg` is ported from
`micro-benchmarks/src/eqlog/math_full.egg` in the PLDI 2023 artifact for
*Better Together: Unifying Datalog and Equality Saturation*:

- DOI: <https://doi.org/10.5281/zenodo.7709794>
- Archive SHA-256: `2f061f4f59fd3404638db0d9ad9d130e008d4c41fdeb58ade30684d8e424607a`

The source preserves the artifact's `Rational` constants and seven seed
expressions.

`math-run-000.egg` through `math-run-100.egg` are sparse checkpoints at ten
iteration intervals. They share `base.egg` through `(include ...)` and are
generated by:

```bash
uv run --locked python scripts/generate_math_checkpoints.py --write
```

Each checkpoint runs the artifact Egglog backoff policy: a per-rule match limit
of 1,000, a ban length of five iterations, seminaive matching from the last
accepted batch, and all-or-nothing match batches. It prints the 13 source table
sizes used by the artifact's Math measurement. The generated comment records
their expected sum from the archived artifact. Positive checkpoints also check
a commutativity equality; the zero checkpoint checks a seed term.

The generator emits an explicit sequence of exactly N `run-with` leaves. It
does not use `repeat`: the experimental schedule language defines exact repeat,
while the core schedule used after term/proof instrumentation may stop a repeat
when its child reports that it can stop. Keeping fixed iteration count in the
generated syntax makes off, term, proofs, and proof-testing execute the same
number of scheduled steps.

`paper_bench.py` independently runs the corresponding archived driver at one
selected checkpoint. Its mutable build copy adds only the documented current-
Rust compatibility and single-checkpoint driver flags; the authenticated
artifact cache remains unchanged.

Depths above ten are intentionally opt-in scaling cases. Their e-graphs grow
rapidly, especially under proof instrumentation.
