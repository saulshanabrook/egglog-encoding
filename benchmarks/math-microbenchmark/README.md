# Math Microbenchmark Checkpoints

The rule set in `base.egg` is ported from
`micro-benchmarks/src/eqlog/math_full.egg` in the PLDI 2023 artifact for
*Better Together: Unifying Datalog and Equality Saturation*:

- DOI: <https://doi.org/10.5281/zenodo.7709794>
- Archive SHA-256: `2f061f4f59fd3404638db0d9ad9d130e008d4c41fdeb58ade30684d8e424607a`

The artifact rules use `Rational`, but every constant has denominator one, so
this current-egglog port uses `i64`. The seven seed expressions come from the
repository's existing `egglog/tests/math-microbenchmark.egg` adaptation.

`math-run-000.egg` through `math-run-100.egg` are sparse checkpoints at ten
iteration intervals. They share `base.egg` through `(include ...)` and are
generated by:

```bash
uv run --locked python scripts/generate_math_checkpoints.py --write
```

For every positive checkpoint, the final check is the integration-by-parts
equality first exposed at that chain depth. The zero checkpoint checks that the
seed term is present. These files make iteration-depth scaling available to the
benchmark runner, but currently use unrestricted `(run N)`. The paper's `egg`
configuration used `BackoffScheduler` with an initial per-rule match limit of
1,000 and a ban length of five iterations. Reproducing that schedule
consistently in `off` and `proofs` modes is follow-up work, so these checkpoints
are not yet schedule-equivalent paper measurements.

Depths above ten are intentionally opt-in scaling cases. Their e-graphs grow
rapidly; depth 20 has exhausted memory before reaching an extended timeout even
without proof instrumentation.
