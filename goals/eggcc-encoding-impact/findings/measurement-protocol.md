# Prospective observation-checker cost protocol

This is a reviewable protocol, not an executed cohort or a statement of readiness. The compiler observer and corrected-source checkpoints, final binaries and exact CLI arguments remain unbound. No build, test, compiler workload or timing ran in this preparation; the frozen collector/guard and E1 source files were read and remain unchanged. Root may authorize the measured blocks only after the host correctness and source gates below are concrete.

This protocol follows the binding comparison conditions in [observation-slice.md](../observation-slice.md) and [comparison review](observation-comparison-review.md). It reports repeated successful compilation costs of a restricted diagnostic package. It proposes no compiler or generated-program speedup, unique logical power, production representativeness or all-input correctness claim. An independent speedup-confirmation cohort is unnecessary for this cost-only report; any later benefit claim needs its own predeclared confirmation under the accepted plan.

## Counts, order and execution boundary

Set `warmups: 1`, `observations: 12`, `timeout_sec: 300` explicitly for each one-case study. The unchanged collector runs three untimed interpreted correctness invocations first, then three warmups without interpretation, then twelve three-arm measurement rounds. Measured order is:

```text
Off Manual Injective
Manual Injective Off
Injective Off Manual
```

Repeat that rotation four times: twelve observations per arm, with each arm occupying each position four times. This is **42 invocations per case**, of which 36 are measured; both admitted cases total 84 invocations/72 measured. The warmup is excluded from summaries and is not claimed to equalize every host cache. Keep the complete declared order rather than adding repeats selectively. The ten-observation collector default must not be inherited here.

Correctness invocations use the same mode flags plus collector-owned `--interp --run-data-out`; successful exits must contain non-null equal source/result output. Their timing is discarded. Timed invocations omit `--interp`; their interpreter fields must be null. Successful rows must complete the normal compiler pipeline, not exit early after an audit or skip the declared pass/extraction work. Bind full-pass behavior with the same-source/flags correctness evidence and normal receipts, without turning on extra timed instrumentation. The source interpreter/observer distinction matters: supported observation evaluation remains part of Manual/Injective compilation cost even when whole-program `--interp` is absent.

The primary time is `run_command.wall_sec`: parent monotonic elapsed time beginning before temporary output-file setup and Popen and ending when `wait4_process` returns. It includes child launch/startup, parsing, the actual mode's observation work, optimizer schedules, audit, Tiger/extraction/reconstruction and compiler JSON receipt writing. It excludes the prelaunch host-readiness guard check, post-wait guard close/process-group cleanup, collector provenance hashing, compiler-receipt loading/verification and figure generation. The supervisor/guard is common to all arms, and its live monitoring can still affect execution. Do not replace this boundary with `eggcc_compile_time` or subtract startup without a separately declared measurement.

Memory is the platform-normalized **`wait4` child `rusage.ru_maxrss`** reported by the reused runner. Retain raw bytes and the explicit scope in rows/tables/figures. This is not simultaneous process-group peak, host usage, combined live EggCC+Tiger RSS, or storage per disequality pair. OS child-resource accounting applies. The guard's sampled group RSS is a separate operational mechanism, not a replacement measurement. No generated-program runtime or native adapter is part of these blocks.

## Host exclusivity, guard and pause rules

Root owns the shared timing window. Start only after all goal/compiler/encoding builds, tests, public smoke, other collectors and known unrelated host builds are terminal. Preserve a process inventory and host/OS/architecture/power-state record immediately before and after the block; record any observed interruption or unrelated work. Use one sequential collector, fixed common thread/environment settings and an unchanged host setup. A process snapshot alone does not prove exclusivity; the coordinator must reserve and supervise the window.

Set **`EGGLOG_BENCH_MEMORY_GUARD=1` in the common outer collector environment**. Do not put a different value in any arm: child `env` alone cannot activate the parent guard. Retain the outer command/environment policy separately as well as the effective child environment hashes. The reused guard requires normal host pressure and a 2 GiB headroom reserve, with a 10 GiB group RSS ceiling, 100 ms group sampling and 500 ms host checks. It is a sampled safeguard, not a hard allocation limit. Its resource stops cannot be accepted as valid measured compilation time.

Predeclare these rules for both blocks:

- Any nonzero exit, signal, timeout, guard refusal/stop, missing/unequal correctness output, missing receipt/measurement, incomplete pass coverage, unsupported/unexpected observer coverage, source/input/binary/configuration hash drift or accidentally enabled query probe stops the block. Keep every checkpoint row, stdout/stderr/receipt and partial diagnostic evidence. Verification failure prevents figures.
- If unrelated build/test/collector activity, sleep/power-state transition or other material host interference is observed, stop before the next launch; preserve the complete affected cohort and an explicit invalid/interrupted block receipt even if collector verification alone passes. Never salvage selected favorable rounds. Do not cancel unrelated owners' work unilaterally.
- After resolving the cause, a replacement complete block needs a new manifest/result directory and a recorded reason before launch; preserve the failed/interfered block and all its rows. Do not append, overwrite, drop outliers, selectively retry arms or reclassify an unfavorable measured run as a diagnostic. A high but valid cost or neutral/regressive result is retained, not a pause trigger.
- No automatic cohort expansion follows from an unattractive/noisy median. Report the twelve raw observations and their variability. Any changed timeout, source, arm set, count or host setup is a new declared block, not continuation of this one.

Expected original-MAX checker aborts are **preclassified diagnostic invocations** outside these successful-control manifests. They are not omitted measured samples. Retain their nonzero exits, partial pass stage and witness, and label any timing as time-to-detection only. A failure inside a declared successful-control block remains a failed block; it cannot be moved into that diagnostic class after seeing its outcome.
