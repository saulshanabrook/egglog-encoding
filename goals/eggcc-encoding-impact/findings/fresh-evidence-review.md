## Source findings

- **Allocation is per enabled optimize call.** DAG `lib.rs:973–985` filters Off, allocates before the pass loop, clones the config locally and substitutes only the prepared evidence directory. The caller's root configuration is not mutated. Every pass receives the same locator; direct `build_program` callers explicitly pass None and retain their documented fresh prepared-directory behavior. The API reuse test (`src/observation_tests.rs:116–157`) runs the same configured Run twice, checks distinct children, unchanged caller root, exactly two children and all three completed pass groups. Its execution result is the compiler owner's evidence, not a test rerun by this reviewer.
- **Existing children are not overwritten.** `observations.rs:65–123` creates/canonicalizes the root and uses atomic `create_dir` on a PID/counter child. Only AlreadyExists retries, bounded at 1,024; permission/storage/other errors return explicit backend errors. PID reuse and independent processes therefore cannot reuse an existing child merely because their counters start alike. The child is persistent. Prepared passes retain `create_dir` freshness refusal (`:624–631`). Mode/root/PID/requested-root/actual-directory metadata is consolidated in the initial index rather than a duplicate `invocation.json`; those identities survive later index replacements, satisfying the locator contract.
- **Index transitions preserve a last committed state.** `atomic_json` (`:57–63`) writes a same-directory NamedTempFile, syncs the file and persists it over the index. `update` (`:125–168`) verifies the invocation identity before replacing the per-pass file list, appending an event and updating stage/status. Initialization, source-schedule, witness and audit errors update the index before their expected error returns; domain rejection writes its zero-seed receipt then attempts the unsupported terminal update before panic. Audit rejection is recorded before returning to the host and before serialization. Index I/O failures propagate or panic rather than returning successful compilation. Per-pass receipt writes remain the existing non-atomic writes: an interrupted/failed write may leave a partial file, while the last valid index stage is the recovery boundary. This is not crash-proof archival. No guarantee of a terminal index is justified after SIGKILL, storage exhaustion, unexpected panic or power loss; neither the directory entry nor all evidence files receive an encompassing durability transaction.
- **Success/Off result plumbing is compatible.** `EggccTimeStatistics` carries the locator to `RunResult` (`src/util.rs:1050–1062`); its new optional serde field defaults to None and is omitted when absent. The Off test (`src/observation_tests.rs:160–187`) checks both no allocation and omitted JSON field even with an explicit Off ObservationConfig. The collector accepts extra compiler receipt fields while preserving its required successful-exit/non-null equal correctness-output checks. Source construction returns the locator belonging to that actual optimize call, not a mutable root-level latest pointer.
- **Completion needs a pass-count check, not just a string.** The index marks `optimizer-complete` after the configured pass loop, or the existing debug-expression early return (`lib.rs:1103–1122`). Thus `status: complete` means this optimizer call returned, not independently that the cost protocol's three passes or subsequent whole CLI interpretation/serialization succeeded. The post-capture acceptance step must require the declared pass set and successful normal CLI receipt. A zero-cutoff/debug early exit cannot qualify merely because its index says complete.
- **Points, seeds and optimizer work are unchanged by the delta.** The patch changes lifecycle/I/O callbacks and error recording, not the existing point construction, supported traversal, literal/observation seed generation, declaration/audit choice or source schedules. The witness expression's new `and_then` has the same ordering/error short circuit as the previous two `?` operations. The audit remains before serialization/Tiger. No new constructor law, grammar, Expr fact or arithmetic correction is introduced.
- **The new helpers own useful invariants.** Atomic JSON replacement, allocation and index transitions are substantive error/lifecycle boundaries. I found no trivial forwarding helper or unrelated refactor in the delta.

## Collector and diagnostic interface

The successful collector's exact arm argv still supplies a fixed root. Unique child allocation happens inside the compiler; correctness/warmup/repetition need no argument templates, wrapper or collector schema change. Allocation, file sync/rename, index enumeration/writes, enabled-arm stderr and final locator serialization are all inside compilation wall time. Manual/Injective share that package; Off skips it. Keep the whole-package attribution and wait4 child-RSS scope from the [cost protocol](measurement-protocol.md), including its separate disabled E1 probe. Do not describe the observed total as an I/O-free or isolated cancellation cost.

**The unchanged collector does not independently record child PID.** Its row contains argv/cwd/environment/receipt/status/timing fields; `TimingResult` has no PID, and Popen.pid stays internal to `run_command`. Successful cost archival must bind the hash-verified normal receipt's locator to the exact known binary/source/mode/canonical root, unique children and expected evidence. The index PID is compiler-recorded, not independent PID attestation. Do not invent such attestation from a path name.

The compiler emits the JSON locator to **stderr before even the initial index write** (`observations.rs:90–105`), so a failed initial write leaves an identifiable incomplete child when full stderr is retained. The shared runner's bounded error tail can lose that early line, and it discards successful output. Expected detector aborts must therefore use the separate full diagnostic capture, binding actual diagnostic Popen PID plus the full stderr locator/index PID and committed witness. The current delta does not guarantee that a failed cost row retains the early locator; retain the failed block and any discovered children without claiming a complete per-row binding that was not captured.
