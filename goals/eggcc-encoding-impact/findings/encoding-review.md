## Law and implementation checks

- **Directions remain separate.** At `disequality.rs:298–322`, constructor schemas are collected independently of annotation, with a separate `injective` flag. At 361–382 only marked constructors supply forward child-difference witnesses. At 384–405 reverse edges require the same constructor index, the same focused position and equality of every other child column; the parent-result pair is the sole remaining witness goal. Thus `f(a,b) != f(c,d)` permits the second-child conclusion only when the committed first children are equal. Different class IDs alone are never used as equality-sort disequality evidence. The raw primitive mismatch branch is inside the marked forward gate.
- **Typed supported fragment is enforced.** Non-constructor/custom function tables are skipped. Reverse schemas require a unionable output, at least one equality-sort input, no container input and unionability of every equality-sort input. Typed parent-index keys prevent mixing child sorts; matching constructor/position prevents heterogeneous schema comparisons. Reserved `@disequality-` constructors are excluded from reverse indexing, so EE representation applications do not supply unintended structural implications. An ordinary `:internal-hidden` user constructor remains eligible, which is consistent with congruence and is tested. Direct primitive/container/nonunionable query operands remain outside the predicate's type signature; ordinary-mode-only rejection remains unchanged.
- **Committed equality is a real boundary.** Sibling comparison uses stored `Value` equality, without a new union-find pass or injectivity execution. Core read APIs expose stored rows/IDs rather than promising arbitrary mid-update normalization. This is acceptable under the approved committed/rebuilt-graph contract, not a new joint equality/disequality closure. Typed root probing retains the core's global fresh-ID invariant; descendant goals get exact schema sorts. The late-sibling-union and scheduled-injectivity tests exercise normal committed command/schedule boundaries under both schedulers.
- **Finite witnesses and storage remain bounded in kind.** The unordered typed-pair visited set prevents repeated expansion around cycles. Each reverse edge refers to existing applications from a fixed read snapshot. A finite path to an assertion or marked primitive mismatch suffices; an ungrounded cycle cannot manufacture a witness. Two unresolved positions remain unknown even when they repeat the same pair, as explicitly documented/tested. The function accepts `ReadState` and only uses read APIs; local applications, parent index, queue, visited set and fetched row vectors create no graph applications, unions or persistent derived-pair/cache relation. Subsumed rows are intentionally included.
- **Lifecycle/scheduler assumptions are preserved.** Marked metadata is reread from scoped state and the transient index is recreated per invocation, so no new cache can survive pop/redeclaration. Tests include a subsumed unmarked row, late union, pop/redeclare, failed marking declaration, cyclic unmarked applications and a late parent assertion. The naive-consumer test distinguishes equality available only after scheduled injectivity from immediately available committed equality, and confirms contradiction checking is not itself the joint closure. Read primitive context restrictions remain the reason consumers need `:naive`.
- **Diff is focused.** One general parent-index mechanism replaces the unary-only reverse branch; no n-ary special cases, new dependencies, public API, persistent index or trivial forwarding/accessor helper were introduced. Existing helpers retain meaningful read/probe/error boundaries. The tests' only new helper performs a substantive finite closure, rather than wrapping implementation calls.

## Oracle and negative-test assessment

`oracle.rs:24–73` is a separate forward-chaining least-fixed-point algorithm: repeatedly inspect all same-constructor application pairs, add legal marked-forward or sibling-guarded reverse facts to a set, and stop when its size stabilizes. It does not call the production query, build its parent index, walk its BFS or reuse its visited-goal algorithm. Sharing the two mathematical premises is appropriate; traversal and state evolution are distinct.

The matrix is precisely two fixed application-graph partitions (acyclic/cyclic) × 16 assertion masks × 2 encodings, not an exhaustive/random sample of all finite graphs. It checks all 253 unordered/self pairs over 22 named values per combination: 64 combinations and 16,192 queries. The supported partition is fixed in the oracle; it deliberately does not perform injectivity unions. Cross-sort, mixed bool/string siblings, late unions, lifecycle and both schedulers are supplied by separate direct tests rather than being claimed as oracle coverage.

Meaningful negatives include missing witness paths, unmarked forward inference, equal-parent cancellation on unmarked constructors, different constructor names, differing primitive siblings, two unresolved children, repeated unresolved pairs, custom function tables, containers, nonunionable siblings, direct invalid query types and proof/term rejection. Acyclic/cyclic graphs without an endpoint and fixed-count/no-table-growth checks make the test set stronger than implementation-shape assertions alone. ## Nonblocking cost and scope limitations

Every structural query now scans **all eligible constructor rows** and copies their child columns into a transient index before witness search. Parent-list cross-products and queued duplicate edges can be large even though each typed pair is expanded once. Direct stored-assertion hits retain their early return. No speedup follows from avoiding persistent pairs, and a naive consumer may pay this construction repeatedly. Measure that cost on an actual selected consumer before proposing persistent indexes or claiming an analysis improvement; this is an explicit cost boundary, not a correctness blocker for the approved prototype.
