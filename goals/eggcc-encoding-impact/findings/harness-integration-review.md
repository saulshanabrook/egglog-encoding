## Source findings

- **Parent policy is deliberate and correctly integrated.** `processes.py:62–66` obtains the guard from the actual parent environment before applying child overrides. `memory_guard.py:127–138` validates the setting and performs the pre-launch host check; Popen follows at `processes.py:72`. An arm-only setting cannot turn on the parent's monitor; an arm's child setting cannot turn off an already created parent guard. The outer-policy limitation is stated prominently at docs `:23–32` and tested at `test_memory_guard.py:20–63`. Later collections must retain the outer invocation/policy separately: the collector's child-environment hashes alone cannot attest a parent setting overwritten for the child. This is a documented operational requirement, not a claim that the collector independently certifies guard activation.
- **Timeout, interruption and guard cleanup have the intended boundaries.** Children start isolated process groups (`processes.py:79`). The timer kills the group and wait4 reaps the parent (`:165–192`); exceptional paths terminate/reap before propagating (`:89–98`). Guard shutdown also cleans descendants after normal parent exit. PermissionError is accepted only after the owned parent has exited and the process-group snapshot has no non-zombie members (`:150–162`). A guard stop discards invalid elapsed timing, and post-exit child rusage can detect a missed high peak (`:99–120`). Unexpected SIGKILL is recorded with unknown cause, not labeled OOM. The monitor is an operational sampled safeguard, not a hard allocation limit or a stronger reported RSS measurement.
- **Failed correctness cannot leak into successful costs.** The collector checks all correctness configurations first (`collector.py:137–146`), requires successful exit and non-null equal source/result interpreter strings (`:162–188`), then omits interpretation for warmups/measurements. The first failure is retained and stops collection (`:253–280`). Positive finite time/RSS are required for non-correctness rows. Expected diagnostic aborts therefore cannot enter this successful-cohort path, as docs `:115–123` explain.
- **Provenance and partial-result rejection are concrete.** Inputs, binaries and explicitly listed artifacts are hashed; provenance is rechecked before each invocation and at final verification (`collector.py:120–134`, `:217–218`, `:284–319`). Verification checks exact manifest, row count/order, command/cwd, treatment, selected environment hashes, receipts and success. Fresh result paths and atomic checkpoints preserve partial failures. Source/build equivalence, recursive artifact references, the truth of an externally written selected-test receipt, and observation coverage are explicitly outside that byte-level contract. Cross-arm reference-output agreement remains a case-design check: the collector validates source/result agreement within each arm, rather than separately comparing all arms' original-interpreter strings. Common input/configuration/observation semantics still need the externally reviewed case artifacts.
- **Three-arm ordering is supported without a new scheduler.** Cyclic rotation gives ABC, BCA, CAB; twelve observations place each arm at each position four times. The actual collection test at `test_eggcc_encoding_case_study.py:99–114` checks 42 invocations (3 correctness, 3 warmups, 36 measured), per-arm counts, every position, interpretation exclusion and verification. The default remains ten, so the future three-arm study must explicitly request twelve rather than infer it from arm count.
- **Output/report boundaries remain suitable.** Compiler output is redirected to temporary files; successful logs are not loaded wholesale. Error/capability scans use bounded reads. Collector progress and CLI completion/errors go to stderr; JSON and figures go to explicit paths. Timing includes the CLI JSON receipt and excludes interpretation; figure data selects every measured observation, excludes warmups/correctness, and retains per-case variability with no overall aggregate. Reported RSS is normalized wait4 child rusage, not simultaneous process-group/Tiger/host peak.

## Test coverage assessed from source

The tests are meaningful rather than solely implementation-shaped assertions: real test-only subprocesses exercise signals, timeout descendant cleanup, interrupt cleanup, successful RSS/timing, large output, and exact error tails. Guard tests force live cap/pressure/monitor failures and check child/descendant death and discarded timing; they also cover unsafe launch refusal, unavailable monitoring, exact cap boundaries, page accounting, missed post-exit peaks, successful guarded timing and unknown-cause SIGKILL. Collector stand-ins exercise real receipt creation and collection order, outer refusal before Popen with a single retained failed row, non-null/mismatch/malformed output rejection, nonzero exit/timeout, failed measurement stopping, changed binary/input/manifest/receipt provenance, incomplete rows, altered invocation/labels, zero selected tests before launch, interruption, a different cwd and real figure regeneration. The test fixtures are clearly labeled as protocol tests rather than EggCC measurements.
