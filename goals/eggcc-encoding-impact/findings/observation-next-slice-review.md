## Evidence allocation and locator conditions

1. **Allocate once per enabled optimizer call, not per pass.** Atomic `create_dir` with AlreadyExists retry handles concurrent processes and PID reuse; a process-local counter alone does not. Bound retries, distinguish collision from permission/storage/other errors, and return a clear allocation failure without entering optimization under an unrecorded child. Resolve the supplied root to an absolute path after creating it; retain both requested root and actual child. Reusing the same EggccConfig for two API calls must not reuse or mutate its previous child. All passes in one call share one allocated child. Off must perform no allocation, receipt write or locator output.

2. **Preserve the separation from semantics.** Invocation names/paths/counters are evidence identity only. Keep existing point/pass/input token construction and logical seeds unchanged. Clone the enabled config locally for the existing prepared pass layout. Clarify whether public configuration names an evidence root while internal prepared configuration names an invocation directory; direct builder tests must not accidentally allocate a second child or mix both meanings. This is an internal lifecycle distinction, not a new framework or grammar feature.

3. **Keep both success and expected-failure locations recoverable.** The optional normal run-data locator is compatible with the copied collector's existing receipt check, which permits extra receipt fields. Off should omit it/default to None. A success locator must name the exact child/index written by that invocation, and the index must reference its actual pass evidence. For expected audit/domain/source-schedule rejection, update the index before returning/panicking and retain the early stderr locator plus persistent files. Index updates should use same-directory atomic replacement, preserving the previous valid stage if a write is interrupted. Do not claim that an updated terminal index is guaranteed after SIGKILL, disk exhaustion or an unexpected panic; label those incomplete from the last committed stage.

4. **Account for abort-log capture limits.** The unchanged shared runner discards successful stdout/stderr and retains only a bounded failure tail. An early stderr path is therefore not, by itself, guaranteed to survive in a failed collector row. Expected detector aborts already use the separate diagnostic capture, so retain its full stderr and bind the initial locator there. If claiming recoverability for failed cost invocations too, supply an explicit recoverable persistent mapping or retained capture; do not infer that the unchanged collector archives the early stderr line. Successful cost invocations can use the normal run-data locator without that problem. Never write locator chatter to program/report stdout.

5. **Do not treat a mutable evidence root as immutable input provenance.** Keep it outside pre-run source/artifact hashes. After terminal status, the owner can bind the selected immutable child/index/tree to the corresponding run receipt. The copied collector neither recursively archives directories nor independently validates a new optional locator's target. That discovery/archival/identity check belongs to the explicitly named CLI capture/verifier or reviewed post-collection evidence step. Reject a locator pointing outside the expected root, to another invocation/mode, or to incomplete/missing required pass evidence before accepting a successful cost observation. Preserve that same protocol for Manual and Injective.

These conditions close the identified repeated-static-argv collision while preserving evidence. They do not invalidate the existing 37-command matrix, which supplied distinct directories. The compiler, CLI capture/verifier and root result plumbing can own the narrow change; the frozen seven-file collector/guard port should remain untouched. Any needed harness-source modification must return to its owner and receive its own checkpoint/review rather than being folded into compiler work.

The new allocation, index writes and locator serialization are compilation work for enabled arms. Manual/Injective must share them. Off intentionally skips the package. Unless separately instrumented/timed, report total checker-package cost, not isolated cancellation cost or an I/O-free audit. No timing starts until the new source/binary is reviewed and correctness checks pass.

## Minimum implementation acceptance

- Two successful x=1 CLI invocations with **byte-identical argv** and the same evidence root create different persistent children, each containing all three passes and a matching normal run-data locator.
- Two actual MAX checker rejections with that same static root create different retained children, each containing its committed conflict/audit/index and identifiable full diagnostic stderr. Neither invocation enters Tiger after the rejected pass.
- An API test reuses one configuration across two optimize calls, proving allocation-per-call and pass grouping without mutating caller state. Existing malformed/unsupported configuration controls still reject explicitly; Off creates no child or locator.
- Capture/verifier negatives reject stale, swapped, missing or out-of-root child/index references rather than trusting a successful exit plus an arbitrary path string.
- Re-run the affected focused tests and mandatory CLI matrix against a newly frozen uncorrected checkpoint. Preserve development-v2 and its collision limitation. New allocator/index code needs a narrow delta review; broader interpretation code changes are outside this proposal.

## Corrected-control protocol

The proposed exact removal of the two diagnosed sign rules is appropriate as a **localized specificity control**, not a claim that wrapping interval arithmetic is now generally sound. Snapshot whole original interval-file bytes and both full rule bodies, require exactly one occurrence per body, and verify the corrected file is precisely that two-block deletion. Keep an independently frozen uncorrected source/patch/compiler/Tiger package before mutation. The interval file must be added explicitly to that source manifest; the earlier development manifest did not list the unchanged interval source separately.

Keep the mutation/build/capture under one owner while other compiler source edits are quiescent. Record the corrected source package and dependency locks before building; use locked dependency resolution where supported and treat unexpected manifest/lock changes as a new delta, not part of the two-rule control. Freeze corrected compiler and exact sibling Tiger before restoration. Only the controlled interval file may differ between the compared source variants; actual source hashes, not the target directory's current contents, determine each binary's label.

Use try/finally for ordinary exceptions plus the saved original file as the recovery authority. It cannot guarantee restoration after SIGKILL or host failure. Independently verify all final uncorrected source hashes after restoration, including interval bytes and both Cargo graphs; do not proceed to official gates if restoration is incomplete. Keep frozen corrected/uncorrected binaries distinct while the shared build target is reused. The final ordinary root/DAG gates apply to the restored **uncorrected observer** source, with the existing real-bug rejection test active and no unrelated snapshot acceptance.

The separately named driver/oracle should have one fixed contract: MAX must exit successfully with non-null source/result exactly `true\n`, all three native round trips, no checker conflict and all four modes Off/CommonSeed/Manual/Injective. Run the identical driver/input expectations on uncorrected and corrected endpoints; retain its expected red and green results. The original red must be the specific wrong answer/expected checker rejection, not a parser error, timeout, missing runtime, empty selection or unrelated failure. Retain explicit nonzero case/assertion counts and the driver hash. Do not filter the incompatible uncorrected bug-witness test and call the corrected treatment's official full suite green.

Mandatory actual corrected CLI controls remain Off/CommonSeed/Manual/Injective on MAX, with x=1/0/-1/dead controls and explicit unsupported-domain outcomes. Off and CommonSeed succeeding independently are necessary to attribute the corrected result to the source-rule change rather than observation checking. A source-filtered replay or a single passing dedicated driver cannot replace that matrix. Old baseline failures and the uncorrected observer's successful detections stay separate evidence classes.
