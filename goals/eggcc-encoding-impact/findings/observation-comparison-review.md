## Material conditions for the comparison

1. **Keep the E1 probe separate from detector cost.** The proposal adds a pre-schedule query but does not yet say which measured modes execute it. Use a separate diagnostic invocation or explicit toggle, disabled in the principal detector-cost cohort. Otherwise Manual→Injective can include different query success/search work as well as the post-schedule audit and annotation metadata. If measuring that combined configuration deliberately, label the whole configuration and do not attribute its difference solely to the consistency audit. For the old/E1 query contrast, hold the exact exported initialization bytes, wrapper annotation, point records, disequality encoding and ordinary-mode flags fixed. A replay shows query coverage; only the actual new-host CLI/pass/path receipt establishes the host hook. It does not create an old-query full-compiler endpoint.

2. **Limit component attribution when common-seed/no-audit is untimed.** It is acceptable to keep that arm as a correctness checkpoint. Then Off→Manual/Injective total wall/RSS differences measure the full diagnostic package: observation traversal, literal insertion, additional graph state, changed optimizer work, metadata and checking. Manual→Injective includes the documented metadata/rule/representation difference as well as audit execution. These totals alone cannot identify observation collection or audit cost separately. A component-cost statement needs separately defined retained phase intervals or an actually timed common-seed contrast; otherwise report total cost and graph/observation counts without decomposing the delta. Hash and compare the common observation identities/literals and record representation differences, rather than claiming byte-identical initialization.

3. **Run the source-corrected specificity control with observations off too.** In addition to the proposed Manual/Injective successful MAX runs, require corrected Off and corrected common-seed/no-audit to complete all three passes and produce source/result `true`. This establishes that the narrow source correction repairs the original failure independently of added observations/literals. Hold that corrected source choice fixed across any cost comparison; do not compare failing uncorrected detection against successful corrected compilation as a speed contrast. If corrected Off still fails, the specificity control has not been established.

4. **Use explicit successful-run and expected-conflict evidence classes.** Successful cost rows require exit 0, non-null matching original/result outputs, complete pass coverage and successful extraction/reconstruction for the same input/configuration. An expected detector abort instead requires the named observer failure stage, offending Expr pair, same exact feasible point, conflicting primitive payloads, completed pre-audit boundary and confirmation that Tiger was not entered afterward. Preserve its nonzero exit and partial pass coverage as such. An earlier existing Const guard, observer validation rejection, unsupported skip, timeout or unrelated panic is not the new detector's success. The old compiler timing collector expects successful equal-output receipts and cannot accept these aborts unchanged; retain separate diagnostic receipts rather than weakening that acceptance invariant. Time-to-detection belongs only to that labeled failure class, never the successful compilation distribution.

Before sampling, declare the measured arm set and balance its launch orders. With common-seed/no-audit untimed, Off/Manual/Injective gives three arms: use a multiple of three rotation rounds, for example 12 observations each, or separately balanced pairwise cohorts. Do not silently inherit the old ten-observation default for that three-arm block. Record per-pass supported/skipped counts and the same logical observation set for Manual/Injective; zero-observation dead-arm controls alone are not representative audit-cost workloads. The reached x=1 case and corrected MAX can provide successful nonzero-coverage controls if their actual receipts establish that coverage.

## Boundaries already adequate in the proposal

Off must remain the unchanged new-engine pipeline; common-seed/no-audit must preserve the original wrong merge without exposing an earlier existing guard; Manual and Injective must reject the same witnessed invalid merge at the same committed pre-Tiger boundary. This controls the important possibility that new literal Expr nodes change optimization independently of checking. Injective-only annotation/rule metadata is explicitly acknowledged, so it need not be disguised as a matched graph input. The manual direct primitive oracle is an equivalent consistency detector, not a weaker baseline.

The pre-schedule MAX witness is correctly described as a counterexample to Expr equivalence on a common feasible domain, not inequality at every input. Fresh x=1-only and otherwise witness-free distinct-point graphs are necessary negatives; retaining a MAX witness in the same graph can legitimately keep the Expr pair known-disequal. The probe should remain read-only, with unknown accepted normally, ordinary/naive restrictions explicit and no materialized Expr disequality premise added to the optimizer.

Feasibility/type/context/input/token validation, selected-arm traversal, per-pass reconstruction, no Expr/point cancellation from equal observed results, unsupported coverage accounting and zero unreachable-arm observations are retained as prerequisites from the semantic review. A seeded replay is insufficient for these host premises. Successful controls retain full-pipeline output checks; failing detection is a restricted selected-point diagnostic, not all-input verification or a proof of extraction/reconstruction.

Repeated successful release invocations, exact source/binary/Tiger/toolchain/configuration identities and identities of any runtime artifacts actually used, defined wait4 RSS scope, total compilation time, all raw rows/variability and exclusive measurement blocks are appropriate. The current no-benefit claim does not require an independent speedup-confirmation cohort; any later benefit claim requires the approved predeclared independent confirmation. No native adapter or generated-program runtime measurement is needed for this slice.

No further material comparison omission found within this bounded review. Reassess if the implementation needs arbitrary semantic facts, a general tracer, broader effect/call/loop semantics or a different manual contract; those are outside this consent.
