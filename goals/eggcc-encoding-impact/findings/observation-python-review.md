## Required corrections

1. **The cost API rejects every approved timed receipt.** `observation_evidence.py:96–108` labels `archive_success_receipt` the cost post-capture step but requires non-null equal interpreter fields. The accepted cost invocations omit `--interp`, so both fields must be null; the unchanged collector explicitly enforces that. Thus an otherwise valid measured row cannot be archived by this API. The current positive test only uses an interpreted receipt and misses the integration boundary. Make the evidence step phase-aware and bind it to the already verified collector row and the case/arm's separately validated correctness/reference-output evidence. Preserve non-null equality for correctness and null outputs for warmup/measurement; do not weaken the collector or turn on interpretation during timing. Add a valid timed-row positive and failures for absent/mismatched correctness linkage or wrong phase/output contract.

2. **Whole-tree archival follows unvalidated root-level symlinks outside the child.** `validate_evidence:43–50` confines per-pass file entries, but it does not check other entries at the invocation-child root. `archive_tree:84–90` follows `is_file`/`read_bytes`, and default `copytree` dereferences symlinks. A complete valid child plus `child/extra -> /outside/regular-file` therefore reads, copies and hashes that external file; before/after/copied dictionaries can agree and acceptance succeeds. This is a direct source counterexample to the required complete-tree containment guarantee, not a tested exploit. Validate the entire tree before any read/copy; since compiler output needs no symlinks, rejecting symlinks and non-regular/unexpected entries is the narrow solution. Include a root-level external-file symlink and a directory-escape negative. Also resolve the output destination before the source/destination ancestry check; lexical relative or symlink-aliased destinations must not evade the outside-source requirement.

3. **The index's file list can hide missing required replay evidence.** `validate_evidence:47–50` requires disk entries to equal the index, then reads observations/audit/committed files and only checks that serialization-entry exists. It never requires `initialization.egg` or `source-schedule.egg`. Delete either from disk **and from the indexed list**: the sets still agree, all remaining checks can pass, and a supposedly complete tree is accepted without its replay input/schedule. Require the actual per-outcome mandatory file set, not just consistency with the supplied list; parse the required serialization marker and check the relevant audit/committed stage/mode/outcome identities. Add a missing-file-and-index-entry negative, rather than only deleting an indexed audit file. This is necessary evidence completeness, not a request for a general malformed-JSON framework.

The new cost association should also make its caller precondition explicit in code/API: `record_id` plus hashes of arbitrary supplied binary/source-manifest paths are not independently verified association with a collector row. The accepted row's receipt hash, actual binary identity, arm mode/root and source artifact identity must be checked or supplied through a named already-verified cohort step. Successful collector rows have no independently captured PID; preserve the current honest `independent_pid_available: false` rather than inventing one.

## Corrected-control driver gate

The normal green path in `check_corrected_specificity.py:27–76` is appropriately fixed: all four modes run, every passing mode needs exact `true\n` source/result, the logs must contain passes 0/1/2 and three Tiger egraph files must exist; enabled modes additionally archive accepted complete evidence and reject committed conflicts. It neither ignores the ordinary uncorrected regression test nor changes the expected answer between endpoints. Normal expected Off/CommonSeed wrong answers do not short-circuit the loop.

**Driver exit 1 alone is not the required valid original red.** It is also returned for timeout, incomplete pipeline, domain/evidence error or any other failure; wrong output and incomplete pipeline share a classification. Missing/malformed command or run-data JSON outside the inner archive try block can terminate the whole loop before four rows/summary are written. Before controlled mutation, require a source-bound four-mode regression-signature check: Off and CommonSeed must exit 0 with source `true\n`, optimized `false\n` and all three native passes; Manual and Injective must have the named witnessed pre-Tiger rejection. Require all four selected records, no timeout/parser/missing-runtime/unrelated failure, then retain that valid-red receipt. This can be a driver summary field or a separately named precondition; keep the fixed corrected oracle's own exit red. Malformed-capture/early-error checks must not be mistaken for that expected red. Only then run the same driver bytes on the corrected endpoint and require four exact green results. Record every mode's classified outcome or explicitly fail the whole capture as incomplete.

The driver currently hashes its binary/source manifest only in the summary. Final provenance still needs the frozen source/build package and actual capture-runner/helper identities; merely naming a source manifest does not establish that a binary came from it. Retain explicit capture return-code/receipt consistency and the full logs used for the pass/native checks. These requirements preserve the existing same-byte oracle plan rather than adding another compiler treatment.

## Repeat receipts and tests

`repeat_evidence.py` uses the same compiler argv for each pair, checks distinct children, validates full diagnostic stderr/PID, and copies each successful shared run-data JSON into its per-run directory. That is a meaningful repeated-static-root check, separate from study timing. There is one reproducibility gap: `archive_capture` always rereads the historical `--run-data-out` pathname from argv. After repeat 2 overwrites `static-run-data.json`, revalidating repeat 1 reads repeat 2's locator and fails even though `run-0/captured-run-data.json` still preserves the original bytes. Explicitly bind/hash the retained per-run normal receipt and let revalidation use that copy without rewriting historical argv; check revalidation after the second repeat. This does not assert that the already archived first child or full stderr was lost.

The fifteen checks in `verify_evidence_negatives.py` are useful: they derive a relocated real complete tree, reject changed PID/mode, incomplete/missing passes, a pre-native stage, missing audit, wrong root/index, changed audit/observation content, duplicate child and bad interpreted outputs. They are not merely forwarding assertions. They do not cover a valid non-interpreted cost row, full-tree symlinks, removing a mandatory file together with its index entry, or the specificity driver's four-mode valid-red classification. Those missing cases explain why the current positive count does not close the findings above.

## Supported parts and scope

Timeout/kills and unexpected terminal statuses are rejected. Full diagnostic stderr must contain exactly one locator, success stderr and normal receipt must agree, and diagnostic PID is checked against the index. The helpers are narrowly source-owned post-capture tools, not a new collector/framework/native adapter. The reported 23 archives remain retained evidence for manual inspection; these source findings require revised helper checks before claiming automatic acceptance guarantees.
