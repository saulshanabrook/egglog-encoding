## P1 terminal supersession

**The supersession is defensible as portfolio deduplication, not as a failed
packing theorem or a backend falsification.** The exact surviving producer is
still `pack32-screen/source.bril`: guarded U32 fields and masked backedges
produce `P32(a,b)=P32(c,d)` and `P32(c,a)!=P32(a,b)` before the translated
component comparison. Its soundness requires both initial field bounds and
preservation on every backedge. These are real extra admission obligations;
general wrapping `Add` or `Mul` must not be marked injective.

The producer differs from Route and Parts32, but the proposed generic work is
already represented by actual-host evidence:

1. Route's tagged `Route(p,a,b)` cancellation produces `a=c` and `b=d`, as
   packing cancellation would; its equal dynamic sibling is causally required
   by reverse reasoning, and its `a=c` rescue restores the downstream result.
2. Route's unmarked Add reverse step and marked odd-multiply forward step
   exercise the same inference roles as P1's reverse-congruence use of Pack32
   and marked `Shift7`. Reusing a marked constructor's ordinary congruence
   contrapositive does not add a new reverse law.
3. Both export only the exact contextual target `Eq=false`. Parts32 supplies a
   separately measured combined-mechanism instance of that consumer. P1's
   remaining additional work is bounded packing/domain recognition, not an
   uncovered generic encoding operation or a distinct compiler consumer.

Accordingly, ledger row 43 honestly states that this is supersession by actual
combined chains and explicitly disclaims P1 speedup, successful P1 integration
and backend rejection. Parts32 alone would not justify that argument: it does
not demonstrate P1's multi-child cancellation. Route supplies the missing
comparison. Nor does this disposition show that P1 would have no additional
runtime benefit; the original native screen remains positive.
